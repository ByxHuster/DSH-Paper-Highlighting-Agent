## 这是什么？

**Paper Highlight Agent** 是一个跑在 DeepSeek Harness（`dsh`）里的「论文多色高亮助手」：

1. 你丢给它一篇论文 PDF；
2. 它把论文解析成网页，并**逐节提出语义高亮**（五色标注）；
3. 你在浏览器里审查 / 修改每一处高亮；
4. 它从你的修改里学习你的偏好（颜色语义、密度、粒度），越用越准；
5. 审查完的论文可以**一键导出**成带高亮的 HTML 或 Markdown，拿去分享 / 放进笔记软件。

一句话：**给 PDF 论文做「带注释的高亮读书笔记」，并且 Agent 会越读越懂你的口味。**

## 快速开始

**前提**：已安装 `@deepseek-ai/dsh`，且已创建 `paper` profile（含 MinerU API key 配置，见设计文档 / 部署文档）。

**启动**（在任意目录）：

```powershell
dsh --profile paper --port 3081 --no-open
```

然后浏览器打开 <http://127.0.0.1:3081>，进入「论文」标签页。

> ⚠️ **端口纪律**：`3081` 是你在用的这个 Web 会话。**不要自己 kill / 重启它**；需要重启（例如更新了宿主代码）时由你来操作，重启后刷新页面即可。

## 完整工作流（一次论文审查）

| 步骤 | 谁来做 | 说明 |
|---|---|---|
| 1. 提供论文 | 你 | 把 PDF 文件交给 Agent（或放到 `D:\aa\data\` 对应目录），Agent 调用 `parse_pdf` 解析成结构化文本 |
| 2. 全局通读 | Agent | 通读全文，产出「论文地图」+ 每节高亮计划（预期颜色 / 密度 / 跳过节），**先给你看计划** |
| 3. 逐节 propose | Agent | 一次只做一节：按计划 + 你的画像 + 领域背景，提出候选高亮（颜色 + 理由） |
| 4. 审查 | 你 | 在 GUI 里接受 / 删除 / 改色 / 改范围 / 手动新增 / 写备注（见下方快捷键） |
| 5. 标记节完毕 | 你 | 每节审查完**点击该节章节标签**（一键审批通过该节全部候选 + 标记已审；v0.5.4.3 起原「标记本节审查完毕」按钮已下线）→ Agent 做章节反思，产出画像更新提案 |
| 6. 确认画像提案 | 你 | 在「提案」面板或直接对 Agent 说「确认提案」→ 偏好并入画像（可审计、可回退） |
| 7. 论文完毕 + 导出 | 你 / Agent | 全部节审查完（或说「论文完毕」）→ Agent 产出**论文级反思**（`paper-reflection.md`）→ 你点「导出」下载 HTML / Markdown |

## GUI 操作指南

### 主视图（「论文」标签页）

- **顶部工具栏（v0.5.4.1 起固定在顶端）**：选论文下拉、刷新、「导出」按钮、「**格式化**」按钮（危险操作，见下）、「**重新提出高亮**」按钮（v0.5.4，格式化后让 Agent 再次提出高亮，见下）。工具栏 + 图例 + 审查进度条 + 节列表构成**固定顶栏**——滚动鼠标阅读论文时，顶栏保持在顶端，只有正文滚动。
- **审查进度条**（图例上方）：`已审 X/Y 节` + 进度条 + 「下一个」未审查节提示 —— 刷新页面不丢进度。
- **图例**：五色语义（**v0.5.1 起，语义标签文字用对应的高亮色显示**，色块 + 彩色文字一眼对应；颜色可在画像面板自定义）。
- **正文**：已接受的高亮以 `<mark>` 色块显示，悬停可看理由；点任意色块弹出**操作条**。正文中的公式/LaTeX 片段（如 `N \times D`）按原文原样显示（v0.5.3 起不再做公式转换渲染）。
- **节列表**：各节状态（已审 / 未审）。**v0.5.2 起：直接点击某个章节标签（如 Abstract）即可一键审批通过该节**——该节的候选高亮全部被接受，同时标记该节审查完毕；即使该节 Agent 没有提出任何高亮，点击也会直接「通过」该节（标记已审，提示「无待审批高亮，已标记审查」）。**v0.5.3 起：按住 `Shift` 再点击章节标签 = 「反选」（批量恢复待审）**——撤销该节的一键审批：该节已接受（accepted）的高亮批量恢复为**待审**（proposed，回到候选队列），该节状态恢复为**待审查**（pending，✓ 消失），方便重新逐条审查；普通点击仍为审批通过。**注意：反选不是批量否决**，已否决（rejected）的高亮不受影响。**v0.5.4.3 起**：原「标记本节审查完毕」按钮已**下线**（它与章节标签点击功能重叠，且依赖滚动定位不稳定）——标记已审统一用「点章节标签」。

### 操作条（点中一处高亮后出现）

| 按钮 | 作用 |
|---|---|
| 接受 | 采纳这处候选高亮 |
| 删除 | 移除这处高亮 |
| 5 个色块 | 改色（换成其他语义色） |
| 改范围 | 进入「重新选文」模式，用鼠标重选覆盖范围 |
| 备注输入 | 给这处高亮写一句注释 |

### 快捷键（论文视图、非输入框内有效）

| 按键 | 作用 |
|---|---|
| `1`–`5` | 把当前选中的高亮改为第 1–5 个颜色 |
| `A` | 接受当前高亮 |
| `D` | 删除当前高亮 |
| `R` | 改范围（进入选文模式） |
| `Esc` | 取消（关操作条 / 关导出框 / 退出选文） |
| `E` | 打开 / 关闭导出对话框 |

> 「新增高亮」没有快捷键 —— 它依赖鼠标选中正文文字（选中即出现「新增高亮」入口）。

### 导出

- 点工具栏「**导出**」→ 弹窗里选 **HTML** 或 **Markdown**，可选「**包含未决（proposed）高亮**」（默认只导出已接受 + 手动新增的）。
- 点「下载」→ 浏览器下载一个**自包含**文件：
  - **HTML**：内联样式、无外部依赖，任何浏览器 / 笔记软件直接打开即见高亮 + 图例；
  - **Markdown**：带 `<mark>` 高亮标记 + 顶部图例，适合 Markdown 编辑器 / 笔记软件。
- 导出文件同时落在 `data/<paper_id>/export/` 目录，可随时取用。

### 一键格式化（工厂重置）

想**换新课题 / 转交他人 / 完全重新学习**时，点顶部工具栏「**格式化**」：

- 弹出警告对话框，列出将清除的内容：**所有论文的高亮记录**（spans / 计划 / 去重 / reflections 提案 / 导出产物 / 论文级反思）+ **个性化画像**（`highlight-profile/`，回到冷启动引导）。
- 点「**确认格式化**」执行，点「取消」放弃（`Esc` 也可取消）。
- 执行后：
  - `paper.highlights.json` 重置为空白（可立即重新 propose）；
  - 已解析的**论文正文（`paper.md` / `anchors.json` / `meta.json`）会保留**，无需重新解析 PDF；
  - 画像被清除，下次打开会重新走冷启动引导，从零开始学习你的偏好。

> ⚠️ **不可撤销**：格式化会彻底删除上述数据，执行前请确认。它只清高亮与画像，不删除论文文件。

### 重新提出高亮（格式化后）

格式化清空了所有高亮，正文上方的**空态横幅**与工具栏的「**重新提出高亮**」按钮会提示你让 Agent 重新提出。点击后：

- ① 记录一条**请求**（host 落盘 `data/<论文>/propose-request.json`，`status:pending` 审计标记）；
- ② 把指令「请为《论文》重新提出高亮」**复制到剪贴板**并提示。

然后把这段指令**粘贴到对话**（或直接说一句「重新提出高亮」），Agent 就会执行 global-read（重建逐节计划）→ 逐节 propose。提出高亮必须由 Agent 在会话里执行——按钮把「重新提出」简化成**一次点击 + 一次粘贴**。

## 五色语义与你的画像

默认五色语义（可在「画像」面板改颜色 / 改文字）：

| 颜色 | 语义 |
|---|---|
| 🔴 红 | 核心洞见 / 贡献 |
| 🟡 黄 | 关键定义 / 方法 |
| 🔵 蓝 | 局限 / 风险 |
| 🟢 绿 | 可借鉴 / 启发 |
| 🟣 紫 | 待深挖 / 存疑 |

- **画像**（`highlight-profile/`）由四层构成：颜色语义、规则（密度 / 粒度等）、示例库、统计。你每次「接受 / 删除 / 改色 / 改范围」都是学习信号。
- 你的确认是**唯一**的落库通道：Agent 只产出「提案」，你确认后偏好才并入画像（低置信规则以「禁用候选」形式入库，可在画像面板手动启用）。
- 领域背景：Agent 参考工作区内的 `field-map.md`（领域发展线）判断语句分量 —— 范式转移节点的句子会优先高亮。

## 数据都在哪？

| 路径 | 内容 |
|---|---|
| `D:\aa\data\<paper_id>\` | 每篇论文：`paper.md`（文本）、`anchors.json`（锚点）、`paper.highlights.json`（高亮 + 计划）、`reflections.json`（反思提案）、`paper-reflection.md`（论文级反思） |
| `D:\aa\data\<paper_id>\export\` | 导出产物（`<paper_id>.html` / `<paper_id>.md`） |
| `D:\aa\highlight-profile\` | 你的画像：`colors.yml` / `rules.json` / `exemplars.json` / `stats.json` / `reflection-notes.md` |
| `D:\aa\field-map.md` | 领域发展线（Agent 建议、你也可手工编辑，追加式） |

> 数据根目录解析顺序：profile 配置 `root`（已钉 `D:\aa`）→ 环境变量 `PAPER_HL_ROOT` → 当前目录（兜底）。

## 常见问题（FAQ）

- **刷新 / 重开会话后进度还在吗？** 在。审查状态写入 `paper.highlights.json`，刷新即恢复（进度条按节状态显示）。
- **点章节标签（如 Abstract）会怎样？** **v0.5.2**：一键审批通过该节 —— 该节全部候选高亮被接受（已接受的 / 你手动加的 / 删除的不受影响），并标记该节审查完毕；该节没有任何高亮时，点击也会直接「通过」（标记已审）。**v0.5.3**：**按住 `Shift` 再点击 = 「反选」（批量恢复待审）** —— 撤销该节的一键审批，该节已接受的高亮回到待审（proposed）、该节回到待审查（可重新逐条审查）；**不是批量否决**，已否决的高亮不受影响。**v0.5.4.3**：原来的「标记本节审查完毕」按钮已下线（功能与点章节标签重复且滚动定位不稳），标记已审统一用点章节标签。
- **点章节标签后提示「审批失败（已回读校准）」/「恢复待审失败（已回读校准）」？** 说明正在运行的 3081 还是旧版本服务端 —— v0.5.2/v0.5.3 同时改了服务端（host）。请**重启 3081** 后再点（数据不会被破坏，客户端会自动回读校准）。
- **点「重新提出高亮」后提示「请求重新提出高亮失败」？** 说明 3081 还是旧版服务端（v0.5.4 新增了 `/propose-request` 路由）。请**重启 3081** 后再点；重启前数据不会被破坏。
- **Agent 提的高亮不合适？** 直接删 / 改色 / 改范围即可；你的操作会进入学习信号，越用越贴合。
- **为什么这次高亮更「克制」了？** 画像在收敛 —— 你删得多的地方 Agent 会降低密度；反之会适度放开。
- **导出 HTML 打不开 / 样式怪？** 它是自包含的，直接双击打开即可；若在笔记软件里预览异常，用浏览器打开或换 Markdown 格式导出。
- **正文里的公式显示得怪？** v0.5.3 起已**移除公式转换渲染**（v0.5.1 的 Unicode 转换），正文中的公式 / LaTeX 片段**一律按原文原样显示**——不再出现「衬线斜体 + 浅蓝底」样式，也不再可能出现灰色色块覆盖；需要复制公式时直接复制原文即可。
- **想从零重新学？** 点工具栏「**格式化**」一键清空所有论文高亮记录 + 个性化画像（回到冷启动）；也可以只在画像面板编辑 / 清空对应层（文件也可手工改）。
- **提案面板有未确认的项？** 那是一次「画像更新提案」，确认后才生效；不确认则保持现状，可随时再来。
